### 3-2. 원인 실험: 글꼴을 "처음" 적용하는 데 걸리는 시간

글꼴 파일을 다 받아 둔 상태에서 `fonts-ready`를 붙이고 화면 배치가 끝날 때까지 걸린 시간을 쟀습니다. Lighthouse 휴대폰 측정처럼 CPU를 4배 느리게 하고 Playwright로 측정했습니다.

| 방식 | 파일 수 | 받는 양 | 사전 상세 | 가이드 |
| --- | --- | --- | --- | --- |
| 가변 글꼴 조각 (1~3차 방식) | 14~15 | 페이지마다 약 390KB | 953ms | 826ms |
| └ 굵기를 하나만 쓰게 해도 | 14~15 | 〃 | 635ms | 601ms |
| 가변 글꼴 전체 1파일 | 1 | 2.0MB | 107ms | 72ms |
| 굵기별 서브셋 4개 (400·500·600·700) | 4 | 1.05MB | 178ms | 123ms |
| 굵기별 서브셋 2개 (400·700) | 2 | 525KB | 127ms | 113ms |
| **굵기별 서브셋 3개 (400·600·700) ← 채택** | 3 | 790KB | 93~104ms | 59~70ms |
| (참고) 한 번 적용한 뒤 다시 바꿀 때 | – | – | 20~30ms | 15~40ms |

메인은 610ms에서 48~56ms로 줄었습니다.

**결론**: 걸리는 시간은 글자 수나 굵기 개수보다 **글꼴 파일 개수**에 따라 크게 달라집니다. 브라우저는 글꼴 파일마다 처음 쓸 때 준비 시간이 들기 때문에, 잘게 쪼갠 조각 방식은 휴대폰에서 1초 가까이 화면이 멈칫했습니다.

### 3-3. 이 방식을 고른 이유

- **가변 글꼴 전체 1파일(2MB)**은 가장 빠르지만 휴대폰 데이터로 받기에는 너무 큽니다.
- **글자를 더 줄인 서브셋을 직접 만들면** 더 작아집니다. 하지만 Pretendard 라이선스(SIL OFL)의 "예약 글꼴 이름" 조항 때문에, 고친 글꼴은 Pretendard라는 이름을 쓸 수 없습니다. 그래서 **제작자가 배포한 서브셋 파일을 그대로** 씁니다.
- **굵기 500(medium)은 뺐습니다.** 요약 상자 두 곳에서만 쓰여서 400으로 바꿨고, 약 270KB를 아꼈습니다. 600(semibold)은 작은 라벨과 배지 17곳에 쓰여서 남겼습니다.
- 서브셋(한글 2,350자)에 없는 드문 글자와 한자는 기기 글꼴로 보입니다. 사전과 가이드 글이 모두 서브셋 안에 있는지는 테스트(`tests/seo.test.ts`)가 확인합니다.
- **대가**: 첫 방문 때 글꼴을 약 790KB 받습니다. 이전 조각 방식은 페이지마다 약 390KB였고, 여러 페이지를 보면 조각이 계속 늘어났습니다. 파일은 1년 동안 캐시되어 두 번째 페이지부터는 다시 받지 않습니다. 첫 화면은 글꼴을 기다리지 않고 기기 글꼴로 바로 보여 줍니다.

## 5. 측정 환경

- 로컬 배포용 빌드: `npm run build && npx next start -p 3000`
- Lighthouse 12.8.2 (명령줄), Chromium 141 headless
- **휴대폰**: Lighthouse 기본값 (휴대폰 화면, 느린 4G, CPU 4배 느리게 계산)
- **PC**: `--preset=desktop`
- 같은 컴퓨터에서도 잴 때마다 1~3점 정도 달라질 수 있습니다. 실제 배포(Vercel, CDN)에서는 서버 응답 속도가 달라 점수가 조금 다를 수 있습니다.

## 6. 다시 재는 방법

크롬이 설치된 컴퓨터에서:

```bash
npm run build && npm start                                              # 터미널 1
npx lighthouse http://localhost:3000/ --view                            # 터미널 2: 메인, 휴대폰 기준
npx lighthouse http://localhost:3000/dream/pig --view                   # 사전 상세, 휴대폰 기준
npx lighthouse http://localhost:3000/dream/pig --preset=desktop --view  # PC 기준
```

크롬 개발자 도구(F12) → **Lighthouse** 탭에서도 같은 측정을 할 수 있습니다.
